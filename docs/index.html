How the numbers are made

  1. SLO on the measured points. The laptop can hold as many requests in flight as it can while the p95 time to first token and the p95 gap between tokens stay under the limits. Between two measured concurrency levels the crossing is interpolated.
  2. Little's law. An active user sends a message, waits W seconds for the answer, then reads and types for Z seconds. One request slot that never sits idle therefore serves (W + Z) / W users.
  3. Other GPUs. Generating tokens for a small model is limited by how fast the weights and KV cache can be read from memory, so latency is divided by the ratio of memory bandwidth. The p95 curves are fitted as a straight line in concurrency and solved for the SLO. The KV cache that fits in the card's memory gives a second limit. These rows are estimates, not measurements: a production server such as vLLM would batch better than Ollama does.
  4. Cost. GPUs needed = users / (users per GPU), rounded up; monthly cost = GPUs × hourly price × 730 hours.
